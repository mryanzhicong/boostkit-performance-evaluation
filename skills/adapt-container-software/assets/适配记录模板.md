# 单个软件适配记录模板

此模板用于适配前厘清事实、实施中追踪完整性，不是要原样提交到仓库。填写后把已核实且开发者需要的信息整理进该软件的 README；未知项标为“待确认”，不要猜测。

原指导中的构建、安装、数据、预热、正式负载、指标、清理步骤逐项记录：采用原样、因任务边界排除，或待确认；每项写对应脚本/命令及理由。对外说明只写本次实际流程，不把已废弃的做法混入正式操作。

实施边界：构建软件与工具的位置＝容器内；正式测试位置＝同一容器内；生成文件＝本次任务私有目录；宿主机仅负责 Docker 命令、已同意的离线输入、Framework 解析与结果持久化。任何例外需写出原因并由用户确认。

## 交付完整性记录

下表在实施中逐项更新。状态只填“已验证／未验证／阻塞／不适用”；“已验证”须有可定位的代码、命令或真实产物，“不适用”须写原因。不能用“代码已写”代替实际运行验证。

| 阶段 | 必须核对的内容 | 状态 | 证据或未完成原因 |
|---|---|---|---|
| 任务口径 | 原指导每个相关步骤的采用/排除理由；版本、原版/调优边界、两架构固定负载 |  |  |
| 来源与数据 | 官方来源、校验、离线优先、缺失回退、完整数据集及授权/体积 |  |  |
